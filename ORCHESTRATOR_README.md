# ClimaFuse Orchestrator

`orchestrator.py` is the backend-facing real-time integration boundary.

## Public contract

The backend calls:

```python
from orchestrator import forecast

result = forecast(variable="temperature")
```

or:

```python
result = forecast(variable="precipitation")
```

The frontend-facing shape remains:

```json
{
  "New Delhi": [[value, probability], ...],
  "Mumbai": [[value, probability], ...]
}
```

## Temperature

Temperature is internally represented by two trained probabilistic models:

```text
AIFS temperature timesteps ──> daily Tmax ──> BMA Tmax ──┐
GFS  temperature timesteps ──> daily Tmax ──> BMA Tmax ──┤
                                                         ├─> average -> public temperature distribution
AIFS temperature timesteps ──> daily Tmin ──> BMA Tmin ──┤
GFS  temperature timesteps ──> daily Tmin ──> BMA Tmin ──┘
```

The public output still contains only `temperature`.

The temperature distribution is generated by sampling the separately predicted Tmax and Tmin distributions and averaging the samples. The prototype assumes conditional independence between the two predictive distributions for this final averaging step.

## Real-time execution

For a live request, the orchestrator:

1. identifies recent published 00/06/12/18 UTC model cycles;
2. fetches actual AIFS and GFS temperature timesteps needed for the next UTC day;
3. derives Tmax and Tmin from the available timesteps from a single forecast run;
4. finds the latest common AIFS/GFS daily forecast;
5. applies the trained Tmax and Tmin BMA models;
6. averages the two predictive distributions into one temperature distribution;
7. returns JSON to the backend.

For precipitation, the existing F24 workflow remains in place.

## Fetchers

The real-time orchestrator calls:

```text
./ecmwf_aifs_fetcher.py
./noaa_gfs_fetcher.py
```

The current AIFS fetcher includes transient request retries, backoff, mirror switching and throttling protection. The GFS fetcher remains the existing working implementation.

## CLI

Live temperature:

```powershell
python orchestrator.py --variable temperature --metadata
```

Live precipitation:

```powershell
python orchestrator.py --variable precipitation --metadata
```

Offline test against cached forecasts:

```powershell
python orchestrator.py --variable temperature --offline --metadata
```

## Operational scope

Exactly these ten locations are supported:

- New Delhi
- Mumbai
- Bengaluru
- Kolkata
- Chennai
- Ahmedabad
- Hyderabad
- Pune
- Jaipur
- Lucknow

No arbitrary operational coordinates are accepted.

## Model lifecycle

Training remains offline. The orchestrator never retrains a model during a forecast request.

```text
Historical AIFS + GFS + IMD
            |
            v
      Offline training
            |
            v
  versioned BMA parameters
            |
            v
       Real-time inference
            |
            v
   probabilistic forecast JSON
```
